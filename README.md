# Лабораторна робота №3. RESTful веб сервіси (частина 2)

**Варіант 1. Система «Лікарня».** Лікар визначає діагноз і робить призначення пацієнту (процедури, ліки, операції).
Призначення може виконати медсестра (процедури, ліки) або лікар (будь-яке призначення). Пацієнта можна виписати
з лікарні, при цьому фіксується кінцевий діагноз.

REST-сервіс на Spring Boot 3 (Java 17+). Підтримує запити `GET`, `POST`, `PUT`, `DELETE`, обмінюється даними у форматі JSON.
Дані зберігаються **в пам'яті** на час роботи сервісу (H2), тож база даних не потрібна.

## Збірка та запуск

Потрібна Java 17 або новіша (Gradle завантажується автоматично через wrapper).

```bash
./gradlew bootRun
```

Якщо `./gradlew` не запускається (немає прав на виконання), використайте `sh gradlew bootRun`. Сервіс слухає порт **8080**.

Запуск тестів:

```bash
./gradlew test
```

Збереження даних у MySQL (необов'язково): створіть змінну `DB_PASSWORD` (пароль у репозиторії не зберігається) і запустіть

```bash
DB_PASSWORD=ваш_пароль ./gradlew bootRun --args='--spring.profiles.active=mysql'
```

## Ролі

Роль користувача передається в заголовку **`X-Role`**: `DOCTOR` або `NURSE`. Дії, для яких роль не підходить, повертають `403`.

## Ендпоінти

| Метод і шлях | Опис | Роль |
|---|---|---|
| `POST /patients` | створити пацієнта (`{"name": "..."}`) | будь-яка |
| `GET /patients`, `GET /patients/{id}` | переглянути пацієнтів | будь-яка |
| `PUT /patients/{id}` | змінити ім'я пацієнта | будь-яка |
| `DELETE /patients/{id}` | видалити пацієнта разом із призначеннями | будь-яка |
| `POST /patients/{id}/diagnosis` | визначити діагноз (`{"diagnosis": "..."}`) | `DOCTOR` |
| `POST /patients/{id}/prescriptions` | створити призначення (`{"type": "PROCEDURE\|MEDICINE\|OPERATION", "description": "..."}`) | `DOCTOR` |
| `GET /patients/{id}/prescriptions[?status=done\|pending]` | переглянути призначення, за потреби відфільтрувати за виконанням | будь-яка |
| `POST /prescriptions/{id}/execute` | виконати призначення | `DOCTOR` (будь-яке) або `NURSE` (процедура, ліки) |
| `GET /prescriptions/{id}`, `DELETE /prescriptions/{id}` | переглянути або видалити призначення | будь-яка |
| `POST /patients/{id}/discharge` | виписати пацієнта (`{"finalDiagnosis": "..."}`) | `DOCTOR` |
| `POST/GET /doctors`, `GET/PUT/DELETE /doctors/{id}` | облік лікарів (`{"name": "...", "profile": "..."}`) | будь-яка |
| `POST/GET /nurses`, `GET/PUT/DELETE /nurses/{id}` | облік медсестер | будь-яка |

## Бізнес-правила

- Діагноз визначає лише лікар. Призначення створює лише лікар.
- Медсестра **не може виконати операцію** (`403`); лікар може виконати будь-яке призначення.
- Призначення виконується **один раз**, повторне виконання повертає `409`.
- Виписка можлива лише лікарем і **лише з кінцевим діагнозом** (без нього `400`). Повторна виписка повертає `409`.
- **Виписаному пацієнту не можна створювати нові призначення** (`409`).

## Коди відповідей

| Код | Коли |
|---|---|
| `200` | успішне читання, зміна, виконання, виписка |
| `201` | ресурс створено |
| `204` | ресурс видалено |
| `400` | некоректні дані (порожнє ім'я, невідомий тип призначення, відсутній кінцевий діагноз, невалідний JSON) |
| `403` | дія заборонена для ролі в `X-Role` |
| `404` | ресурс не знайдено |
| `409` | дія суперечить стану (повторне виконання, повторна виписка, призначення виписаному пацієнту) |

Помилки повертаються в єдиному форматі: `{"error": "опис"}`, а для помилок валідації додатково `"details"`.

## Приклади запитів

```bash
curl -X POST localhost:8080/patients -H 'Content-Type: application/json' -d '{"name":"Іван Петренко"}'

curl -X POST localhost:8080/patients/1/prescriptions -H 'X-Role: DOCTOR' \
     -H 'Content-Type: application/json' -d '{"type":"OPERATION","description":"Апендектомія"}'

# медсестра не може виконати операцію: відповідь 403
curl -i -X POST localhost:8080/prescriptions/1/execute -H 'X-Role: NURSE'

curl -X POST localhost:8080/patients/1/discharge -H 'X-Role: DOCTOR' \
     -H 'Content-Type: application/json' -d '{"finalDiagnosis":"Одужав"}'
```

Для демонстрації в Postman імпортуйте колекцію `postman/hospital.postman_collection.json` (змінні `patientId` і
`prescriptionId` заповнюються автоматично, кожен запит має перевірки).

## Структура проєкту

```
src/main/java/com/example/lr23
├── controller/   REST-контролери (приймають запити й викликають сервіси)
├── service/      бізнес-правила (ролі, статуси, виписка)
├── repository/   доступ до даних (Spring Data JPA)
├── model/        сутності й переліки (Patient, Prescription, Doctor, Nurse, Role, PrescriptionType)
├── dto/          запити й відповіді API
└── exception/    винятки та обробник помилок із відповідними HTTP-кодами
src/test/java     автоматичні тести (MockMvc) на всі правила варіанта
```
